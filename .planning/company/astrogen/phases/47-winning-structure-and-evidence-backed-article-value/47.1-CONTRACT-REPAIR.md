# Winning Structure Remote Contract Repair

## Incident

The native article case `30e253a7-42c3-4e21-a5f1-083f07584b3e` repeatedly
cycled between `strategy_input` and `winning_structure`. Its stored input used
legacy nested aliases, while the running Paperclip adapter falsely returned a
local validation success. The real remote `start_winning_structure_run` then
rejected the input with required-field errors.

## System Invariants

1. The remote Winning Structure MCP is the only authority for task-input
   validity. A local adapter must never substitute a success response.
2. Invalid input returns structured field paths and a remote contract version.
3. The native stage may retry only after the input body or the error fingerprint
   has changed. An unchanged invalid payload is a typed pre-start repair state,
   not an automation loop.
4. Every live deployment must have the plugin row, company config, encrypted
   secret binding, registered tools and reachable private MCP endpoint before
   an article case is resumed.
5. Docker restart must restore both the clean Paperclip compose stack and the
   Winning Structure MCP service.

## Applied Changes

- `seo-winning-structure`: contract v1.1 adds `validation_source=remote_mcp`,
  `validation_issues[]` with field paths, and forwards those errors from start.
- `plugin-winning-structure-mcp-agent-tools`: preserves remote validation
  failures and no longer contains the deployed local-success bypass.
- Native pipeline and strategist contracts now require the exact typed nested
  business context and prohibit legacy aliases.
- Activation is idempotent: it restores the plugin DB record, config and secret
  binding if they are missing.
- `migrate-legacy-winning-structure-input.mjs` safely normalizes only existing
  legacy evidence/commitment/bridge fields before a remote lifecycle begins.
- `resume-winning-structure-after-contract-repair.mjs` validates the existing
  case through the live plugin, moves the same case forward, and closes only
  its obsolete technical blockers after the native transition.
- Systemd units now supervise the clean Paperclip compose stack and the MCP
  compose stack after Docker service restarts. UFW permits only
  `172.18.0.0/16 -> 100.98.5.50:8000/tcp` for this private MCP channel.
