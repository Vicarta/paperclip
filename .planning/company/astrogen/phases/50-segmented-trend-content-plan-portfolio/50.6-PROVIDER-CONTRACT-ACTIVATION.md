# Phase 50.6: Semantic Core Provider Contract Activation

## Goal

Make the current Semantic Core MCP contract real in the clean Astrogen runtime:

- provider-backed semantic validation and audience-trend research are available;
- only explicitly configured, bounded operations may spend;
- standalone content parsing is exposed as an evidence-only Paperclip capability;
- provider-reported costs reach the Paperclip ledger when numeric cost data exists;
- the running image cannot silently fall behind the source contract again.

## Decisions

1. The server operator enables `SEMANTIC_CORE_ENABLE_PROVIDER_EXECUTION=true` persistently through a source-controlled Compose override. This enables external provider transport; it does not grant agents an unrestricted paid mode.
2. Paperclip runs plugin version `0.3.15` and stores these explicit company settings:
   - `providerExecutionPolicy=approved_candidate_batch`;
   - `trendLiveExecutionEnabled=true`;
   - `contentParsingExecutionPolicy=approved_bounded_evidence`.
3. Omitted semantic mode remains `mock`; omitted trend mode remains `fixture`. This is a default for accidental calls, not an operational ban on the explicit approved modes above.
4. Provider-backed semantic work is restricted to 1-10 exact candidate keywords, `provider_queue=standard`, no Search Intent, no inline content parsing, and `read_only` or `read_write`. `refresh` and `bypass` remain rejected.
5. Live trend work is independent from semantic candidate validation, uses the `astrogen-audience-trends-ukraine` project, private-project cache with `use_cache`, at most 12 research queries and 30 sources, and server-side four-word SERP-query enforcement.
6. `request_content_parsing` is a separate tool. It may parse at most three explicitly named public URLs per request, with the Standard queue, no browser rendering, no Markdown view, and at most 50 terms per URL. It persists evidence only; it cannot alter semantic membership, create topics, or create articles.
7. A missing numeric provider amount is stored as durable telemetry with `accountingStatus=unknown`; it must not be represented as zero spend. Numeric `actual_cost` is preferred, then numeric `estimated_cost`, and sub-cent values use `amountMicros`.

## Work Plan

### Wave 1: Adapter And Tests

1. Upgrade the Paperclip Semantic Core plugin to `0.3.15`.
2. Add the 15th MCP operation, `request_content_parsing`, to the allowlist, manifest, worker registration and typed fallback argument handling.
3. Add a dedicated execution policy for standalone parsing. Validate URL count, Standard queue, term cap and expensive rendering options before the MCP connection is opened.
4. Persist parsing request/result evidence. When a completed parsing job carries `usage[]`, create one idempotent ledger event per numeric USD cost and persist an explicit unknown-cost state otherwise.
5. Add unit tests for the policy boundary, tool exposure, job result persistence, provider-reported cost, estimated fallback, unknown cost, and duplicate suppression.

### Wave 2: Configuration And Deployment

1. Change the clean bootstrap and plugin manifest from a parked provider policy to the explicit bounded policy above.
2. Update Semantic Core, trend, CMO and strategist contracts so `read_write` is usable only for a named 1-10 keyword candidate batch; all evidence rereads remain `read_only`.
3. Add a source-controlled Semantic Core Compose override that sets only `SEMANTIC_CORE_ENABLE_PROVIDER_EXECUTION=true`. It must contain no credentials and must be installed as the automatic Compose override on the MCP host.
4. Build the plugin and an immutable clean Paperclip image from the currently running base image. The image build must assert the `0.3.15` package, execution policy module, content-parsing tool and cost bridge.
5. Back up clean Paperclip Postgres and restart only `paperclip-astrogen-clean-app`; do not touch the old Paperclip or CMS publication path.

### Wave 3: Live Proof And Drift Detection

1. Verify server health, authenticated MCP initialization, server provider gate, plugin readiness, manifest version, company settings and secret reference without exposing tokens.
2. Run one deliberately bounded semantic provider call with one exact candidate and inspect the completed run's cost telemetry and Paperclip ledger.
3. Run a fixture content-parsing adapter test and a live bounded parsing request only if the semantic provider smoke reports a healthy provider path. Inspect its evidence-only result and cost record.
4. Verify that invalid calls remain rejected before provider use: omitted mode becomes mock/fixture, a batch of 11 keywords fails, `refresh` fails, a five-word trend SERP query is rejected server-side, and a parsing request over three URLs fails plugin-side.
5. Add a deterministic verification script that compares the deployed plugin version/tool surface/settings against Git source and reports a deployment mismatch as an actionable failure.

## Acceptance Criteria

- The Semantic Core server reports provider execution enabled, and a Paperclip-approved one-keyword provider batch succeeds or returns a provider error with durable telemetry; it never falls back to a fake fixture result.
- `paperclip.semantic-core-mcp-agent-tools` is version `0.3.15`, has an execution policy module, and exposes all 15 MCP operations including `request_content_parsing`.
- The plugin permits only the configured bounded paid modes and rejects unbounded/default-expanding calls before network/provider access.
- Content parsing is evidence-only, limited to three URLs, Standard queue and 50 terms/URL; it creates no semantic import, topic or article case.
- Paperclip records every numeric provider amount as a cost event with `amountMicros`; unknown amounts remain visibly unknown in durable evidence rather than appearing as zero.
- A post-deploy verification detects a version, tool-surface, policy, server-gate or cost-bridge mismatch.

## Rollback

- Disable the MCP host Compose override and recreate only `semantic-core-mcp`.
- Restore the clean Paperclip PostgreSQL dump and previous immutable app image.
- Revert the `0.3.15` plugin settings to `disabled`/`false` gates while retaining secret bindings and historic evidence.
- Existing CMS drafts, the old Paperclip deployment, Telegram proactive watches and external provider credentials are not modified.
