# Phase 50.5: Codex OAuth Fail-Closed Recovery

## Incident

An OpenAI refresh token was revoked. Instead of pausing execution and asking
for a reconnect, 22 Codex agents were routed through `opencode_local` to
OpenRouter Claude Sonnet. The fallback later failed on OpenRouter weekly credit
limits and left article stages blocked.

## Architecture Decision

- `codex_local / gpt-5.5` is the only normal harness for leadership, SEO,
  technical, operational, validation, layout and image-runtime agents.
- `SEO Blog Article Writer (Claude)` is the only Claude agent.
- OAuth failure is an infrastructure incident, not a model-routing decision.
- One unavailable harness pauses the organization before it can create a
  cascade of partial work or technical Telegram errors.

## Runtime Contract

`paperclip-codex-oauth-guard.timer` runs every two minutes. A new explicit
refresh-token-revoked error causes one fail-closed transition:

1. create a clean DB backup;
2. pause every active Astrogen agent and cancel active runs;
3. send one idempotent Ukrainian Telegram notification;
4. send one idempotent HTML email to `o.savitsky@gmail.com`;
5. persist the incident run ID and paused agent IDs;
6. wait for operator-managed OpenAI device authentication.

The same failed run cannot send duplicate notifications. Generic provider
errors, temporary network failures and quota messages do not masquerade as an
OAuth revocation.

## Recovery Proof

- OpenAI device authentication completed successfully.
- A direct `codex exec` probe returned `OK` with provider `openai` and model
  `gpt-5.5`.
- 22 fallback-marked agents were restored to their original `codex_local`
  configs after a 124,177,398-byte database backup.
- Seven stale agent error states were cleared.
- Existing AST-1668 and AST-1669 automations resumed without creating new
  article cases; AST-1669 completed and AST-1668 continued in progress.
- Live inventory shows no `opencode_local` agents. Claude remains assigned only
  to `SEO Blog Article Writer (Claude)`.
- The guard systemd timer is enabled and its first checks returned
  `action=none`.
