# Phase 50.3: OpenCode Runtime Home Recovery

## Incident

After the Codex subscription adapter became unavailable, current article stages were moved to the tool-capable `opencode_local` harness. The app volume contained a root-owned `/paperclip/.claude` directory, while agent execution runs as the unprivileged `node` user. Skill injection failed with `EACCES`, and both independent article cases were blocked before OpenCode started.

## Root Cause

The adapter injected skills into `os.homedir()/.claude/skills` before it prepared the child process environment. It did not verify that the directory was writable and did not guarantee that skill injection and the OpenCode child used the same `HOME`.

## Invariants

- Skill injection and the OpenCode child process use the same resolved runtime home.
- An inaccessible legacy home does not block the workflow.
- The first fallback is persistent and instance-scoped:
  `${PAPERCLIP_HOME}/instances/${PAPERCLIP_INSTANCE_ID}/runtime/opencode-home`.
- `/tmp/paperclip-opencode/${PAPERCLIP_INSTANCE_ID}` is the final bounded fallback.
- A fallback is logged with rejected paths, without secrets.
- Remote execution keeps its existing managed-home behavior.
- Independent article cases resume from their current stages; no replacement tasks are created.

## Verification

- Runtime-home unit tests cover the configured-home and persistent-fallback paths.
- Existing local and remote OpenCode adapter tests pass.
- Adapter TypeScript typecheck passes.
- Clean deployment uses a minimal overlay containing only the adapter runtime-home change.
