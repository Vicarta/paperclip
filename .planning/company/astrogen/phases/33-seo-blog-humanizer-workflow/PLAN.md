# Phase 33: SEO Blog Humanizer Workflow

## Goal

Add a dedicated SEO Blog Humanizer lane to Astrogen's article workflow and use
it for newly generated traffic articles before layout/CMS delivery.

## Why

The Humanizer skill already exists, but it was only an optional manager-routed
polish step. For generated SEO articles, the system needs a stable agent lane
after Stage 61 acceptance so articles can become less templated without
reopening the writer/validator loop.

## Scope

- Add source contracts for `SEO Blog Humanizer`.
- Register the agent template in Astrogen agency-core.
- Update CMO routing so generated SEO articles go:
  Stage 59 Writer -> Stage 61 Validator -> SEO Blog Humanizer -> Stage 64/68
  layout/package -> Stage 65 image -> Payload CMS draft -> Telegram draft URL.
- Keep owner/expert-provided "do not change text" articles exempt unless the
  owner explicitly asks for polish.
- Create the live Paperclip agent with wake-on-demand and no timer heartbeat.
- Launch one CMO-owned traffic-article pipeline issue to test the new lane.

## Acceptance

- Live Paperclip has one `SEO Blog Humanizer` agent, not a duplicate.
- CMO contract delegates post-validation generated article polish to that agent.
- Stage 61/64 process docs mention Humanizer as normal for generated SEO
  articles and exempt owner-provided no-rewrite text.
- New traffic article issue is assigned to CMO and running/queued through the
  normal workflow.
- No article text is manually generated by Codex.

## Verification

- Local contract grep shows Humanizer in CMO, Stage 61, Stage 64, and registry.
- Live `/home/paperclip/astrogen` contains the active Humanizer contract.
- Live DB query shows agent config with heartbeat disabled and wake-on-demand.
- Live issue query shows the new traffic article parent issue and initial CMO
  run.
